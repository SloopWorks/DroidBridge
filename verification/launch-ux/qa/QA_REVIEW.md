## Findings and remediation

- The first assertion incorrectly expected an empty startup control socket and mistook the legitimate start-app packet for user input. `initial-startup-control-fixture-failure.log` is retained; the corrected test permits only that exact packet before input and compares unchanged bytes.
- The fixture initially minimized before AppKit launch completed, then redundantly requested minimize again. Explicit test-host `finishLaunching`, a short window-server settling interval, and one deliberate minimize action corrected the fixture. The initial failures are preserved. The final source also avoids activation-policy/window-order changes at first frame and does not reorder a reused preview during attach.
- Introducing black-frame suppression made a running transport an insufficient UI input guard. The shared `acceptsAndroidInput` guard now covers keys, Back, context/clipboard and pointer paths until visible video exists and no status covers it; the held-black control-socket test passes.
- The thumbnail check can classify very dark/sparse legitimate content as blank. The timed explicit reveal action supplies an escape without changing Android capture/PIN policy. The compact layout corrects a concrete minimum-size notice/button overlap.
- Strict fallback Texture readiness initially exposed real unmodified-client stdout buffering. The opt-in production supervisor PTY provides raw, bounded diagnostic relay without modifying scrcpy or replacing inherited port-lease stdin; see `pty-review.md`. The source's exact child PID/parent checks and public metadata constrain fallback tracking. Terminal OSC title bytes are removed before readiness-line matching.
- The new PTY unit test itself initially hung in Foundation `waitUntilExit`; `full-suite-wait-sample.txt` identified the test-only defer. The lead replaced it with finite async teardown and reran the full suite. No process was signaled by this reviewer.
