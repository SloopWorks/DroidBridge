## Installed C05 canonical replay and no-op assertion

Use only a purpose-created app in the QA managed catalog and one authenticated
public NSXPC client. Let all unrelated catalog changes settle; record current
trust, token, package selection/revision, command count and wrapper state. Avoid
installing/upgrading packages or reconnecting during this isolated assertion.

1. Send `export_selection_set` with a recorded request UUID and the opposite
   selection. Observe the actual owner outcome, policy value/revision, and fresh
   catalog token. Require the active/inactive wrapper result actually observed;
   `intent_committed` plus materialization pending is not wrapper readiness.
2. Replay the **same request UUID, operation, payload and client owner**. Compare
   the canonical RPC reply to its original value; it may remain `accepted` even
   after completion. Query `command_status` separately for its truthful terminal
   owner result. Require the same command identity, unchanged policy revision,
   unchanged token and no additional owner command/session. Observe stable token
   over multiple local-status reads; reads alone must not query catalog or churn
   it. Receipt replay is not a new materialization request.
3. Send a **new UUID** with that same selected value. This is a deliberate new
   intent/retry, so its per-package revision may advance and wrapper work may run.
   Once settled, require the selection map and token to stay unchanged. Do not
   demand unchanged wrapper mtime: explicit retry may legitimately materialize it.
4. Restore the original intended value with another new UUID, verify actual
   wrapper eligibility and a token change only if the selection map changes.
   Repeat or bind the matching phone-origin choice path. The phone's paired
   `catalog_preferences` event must not duplicate its exact command's effect.

Source basis: `applyExport` returns an existing exact command before policy work;
otherwise it loads accepted policy and advances the token only when the entire
cached selection map differs. Equal policy revision with no broker receipt is an
unknown crash gap, never permission to rerun materialization. A new revision with
unchanged value is committed intent but not an actual map change. These assertions
must exclude unrelated package/reset/reconnect events, which independently and
correctly invalidate the token.
