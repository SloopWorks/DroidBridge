# Package caller-Python selection

`package.sh` captures the caller's `python3` before adding Homebrew or changing the working directory. It anchors relative executable paths, checks that the interpreter is executable, and preflights all standard-library modules used by packaging helpers, including plistlib/expat and zlib. The selected directory stays before Homebrew in inherited PATH; every direct package Python command invokes the selected executable with quoted argv. No optional override, dependency repair, global PATH change or DYLD/PYTHON override was added.

The exact source header, ending immediately before VERSION assignment, was executed in fresh `/bin/bash -c` subprocesses. Following the header, both inherited `python3` and direct selected-interpreter commands imported plistlib/expat and decoded a sample plist. Caller PATH cases: Python.framework3.14, a private python3 symlink in a directory containing spaces, and that same directory through a relative PATH. All three passed. A caller PATH selecting the broken Homebrew interpreter failed during preflight with the actual XML_SetAllocTrackerActivationThreshold error, before any build/staging work or subsequent interpreter commands. The test verified no inherited PYTHON/DYLD overrides. Detailed output and exact source SHA are in results.json and the four logs.

`bash -n scripts/package.sh` and `git diff --check` pass. No build, bundled executable, GUI, ADB/device, dist or installed-bundle operations occurred. Root retains the original failed build log/staging and owns the actual release rebuild.
