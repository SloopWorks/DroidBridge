# Independent audio routing review

**Verdict: APPROVED for the tested Android 15/API 35 and Android 17/API 37 emulator pipeline, both video backends, on exact installed 0.1.8 build 14.** No remaining release-blocking product defect was found. Physical audibility and the limitations below remain explicit. No decoder log, alive process, successful compilation or output-initialization marker is counted as proof of audible sound.

## Reviewed boundaries

Audio is device-wide, with independent video sessions continuing to use no-audio. The route enum permits Phone, Mac output capture, and Mac + Phone playback duplication; no microphone route exists. The audio client's argument array disables video, control, window and power-on, requires audio, uses raw PCM and an explicit serial/leased port. Mac + Phone does not silently substitute output capture on failure. Existing keyboard-HIDE video behavior must remain intact.

The separate pinned client patch emits its exact readiness marker only after successful SDL output-device-stream open and successful resume. This proves output initialized, not nonzero samples or physical speaker audibility. Production normal operation does not record audio. The test-only SDL sample observer demonstrates causal tone/nonzero PCM separately and is absent from the shipping runtime.

One exact-serial advisory lease is held by the crash-independent supervisor through client teardown and cleanup. The GUI observes shared ownership rather than killing another host's subprocess. Preferences remain bounded to 32 serial routes and 16 KiB with locked atomic updates. Missing output and unreadable preferences fail to visible alternatives while video remains independent.

## Findings and remediation tracking

1. **Exact tunnel cleanup (remediated; source/fixture verification PASS):** the first router revision supplied only serial and local TCP port. Current supervisor compares the exact serial/TCP/remote-socket identity. `qa/supervisor-fences.json` executes exact removal, absent mapping, foreign replacement and unrelated serial cases against real C code with fake ADB. The foreign cases remain untouched. The client patch also delegates supervised cleanup, preventing its own unguarded upstream removal; `--no-rebind` prevents initial replacement. ADB has no atomic compare/delete primitive, so this does not promise exclusion of arbitrary external mutation between the query and remove.
2. **Bounded status reads (source and final suite PASS):** initial retry/failure reads loaded whole files before checking their lengths. Current code uses bounded no-follow regular-file/UID-checked reads. Bounded refusal cases pass in the final source suite; final installed behavior remains a separate gate.
3. **Failure-admission race (initial fence verified; final full suite passed):** checking a shared failure latch only before lock acquisition leaves a race with another owner publishing failure. `qa/supervisor-fences.json` verifies matching failure under the owner lock exits 77 without launching; a new retry identity succeeds. An additional live-supervisor SIGUSR1 timeout fixture proves the supervisor publishes its matching failure latch and refuses a successor, rather than relying on a late GUI write. The systems owner has moved timeout failure publication into the supervisor while locked, added bounded retained diagnostics and generation fences after awaited I/O; the final 153-test suite passes against these changes.

4. **Capacity escape safety (fixed and independently tested):** the initial default-Mac policy could capture a 33rd, unrecorded device while its Phone preference could not fit the 32-entry bound. The final policy defaults unrecorded devices to Phone at capacity, preserves accepted entries, refuses Retry bypass, and drains an existing default capture when capacity is reached. Both new QA regressions pass; no limit was weakened and no historical preference was evicted.

5. **Observer perturbation (test-only fix source-reviewed):** the initial observer performed file I/O on the audio callback and had an earlier recursive-interposition fixture fault. The revised observer uses a bounded SPSC ring and background aggregate-metric writer; dropped frames are explicit. Original failure and all-zero silence controls remain non-acceptance evidence.

6. **Legacy writer erasing Phone intent (production fix implemented; final suite passed; included in installed build 14):** older wrappers rewrite the old global preference schema and could erase a new audio-route field, returning a device to default Mac capture. Audio now has an independent authoritative `audio-preferences.json` store via `DeviceAudioPreferences`; old global writes cannot mutate that file. New independent tests model the legacy Codable writer, a conflicting prototype field in the global store, 32/33 route bounds and a bounded held-lock refusal. The final suite passes both independent store regressions. This is a source/store regression, not an actual legacy GUI-process test. The intermediate `9917018…` package predates this fix and is not the approved release candidate.

7. **Real installed readiness failure (confirmed and fixed; all four installed backend/API matrices PASS):** candidate `2fea8581…` actually initialized SDL, but the pinned client emitted an OSC terminal-title sequence on the same line as `INFO: DROIDBRIDGE_AUDIO_OUTPUT_READY`. The router’s exact raw-line comparison missed the valid receipt and timed out after 20 seconds. The failed run was moved to a timestamped `native/api35-before-*` directory before a fresh run; it was not relabeled as success. Its failed audio log contains the actual prefix/marker. Source now strips only complete bounded terminal sequences before retaining exact-line matching. New parser negatives and an independent real-supervisor/fake-client regression cover this observed structure; all pass in the 153-test source suite. The older `2fea8581…` and `9917018…` packages are both intermediate, not approved release artifacts.

## Final verdict and limits

The installed host/client hashes match `install.json`, and the product inputs match the frozen candidate manifest. The QA artifact binding and refreshed reviewed-input hashes record the final scope. Test observers/metrics are absent from the installed app. Final verification-only driver manifest refresh is handled separately from packaging; calibration and capture changes do not modify product binaries.

Final focused regression evidence under `regression/` also passes the shipping no-device launch UX and wrapper failure-retention harnesses; these are isolated AppKit/process fixtures, not extra real-Android runs.

All planned release gates have executable evidence: four actual backend/API matrices, separate copied-wrapper ownership/crash handoff and actual owned-emulator restart, plus source tests and real-supervisor failure/lease fixtures. Both routes, multiple video windows sharing one capture, Phone, failure/Retry alternatives, screen OFF, live rendered content and exact cleanup are covered. Two-serial ownership is verified with isolated process tests, **not a live simultaneous two-device run**. No microphone capture source, silent route fallback, global Android volume/power setting mutation or production recording was introduced.

The locked desktop limits physical focus testing; public AppKit/SDL injection is client event-path evidence. Physical Pixel, speakers/handset audibility and Bluetooth/output-device hardware transitions remain manual validation. Protected/app-opt-out audio, calls, vendor policy and Android capture limits remain unsupported by these synthetic media fixtures. The 2% spectral absence tolerance is a measurement bound, not zero unwanted energy. Handoff is exclusive and may have a gap. ADB cleanup uses exact identity checks, not an atomic compare/delete primitive against arbitrary external tools.

## Distribution limitation

`repeated-build.json` documents two successful consecutive package runs with identical signature-stripped host code payloads, but nonidentical signed bundles/archives due to staging-path/version metadata and icon-helper JAR timestamps. This release is buildable and installable; no byte-for-byte reproducibility, Developer ID notarization, or physical speaker/Bluetooth/Pixel validation is claimed.
