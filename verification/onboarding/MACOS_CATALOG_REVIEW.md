# macOS catalog implementation milestone

Source ownership: `Sources/DroidBridge/MacAppWrapper.swift`, `Sources/DroidBridgeCore/ManagedApps.swift`, `Sources/DroidBridgeCore/ManagedAppsCopy.swift`, `Tests/DroidBridgeCoreTests/ManagedAppsTests.swift`, and `scripts/verify-managed-apps.{swift,sh}`. No Android device/session was used for this milestone.

The catalog fences reservations and publications with a per-user cross-process flock and bounded JSON manifest. Expensive Android icon work, full bundle cloning/signing and Launch Services calls occur outside that lock. The manifest binds all decoded record, reservation, publication and registration paths to derived device/package identities. Public-path launches require active desired availability and active physical location, an exact owned bundle, and no incomplete publication.

Offline decisions deny dispatch immediately. A durable unregister action runs while the old public URL still exists; its acknowledgement moves the exact owned bundle into `.noindex` storage without killing an existing process. A generation replacement or explicit validated manual-wrapper adoption waits for old-URL unregistration before retaining the previous complete bundle privately and publishing the successor. Manual adoption preserves saved app name/backend/device/package; unknown and running wrappers are refused. Per-device bundle identities differ from old package-only manual identities, so previously pinned Dock aliases may refer to the archived old copy and should be replaced with the managed wrapper. No unrelated applications are scanned recursively, overwritten or deleted.

Dispatch completion rechecks the action generation. If a registration raced a newer offline decision, a compensating unregister remains in the manifest; a successor action is not acknowledged accidentally. The system worker owns finite execution/retry of these actions.

Stable app filenames consist of a bounded friendly label plus a package-hash suffix, pinned in the first record and retained across later label changes. This is necessary because actual macOS Spotlight imports `kMDItemDisplayName` from the filename even when CFBundleDisplayName/InfoPlist.strings contain a different name. Those bundle-local names are still emitted for native application identity.

`catalog-tests.txt`: 10 focused XCTest cases pass, covering availability, unregister-before-move, independent device identities, concurrent reservation refusal, symlink/foreign metadata refusal, running update refusal, generation replacement/backups, manual adoption/config preservation, cancellation after journal admission, stale registration compensation, interrupted location recovery, malformed reservation/action paths, dead-owner successor admission, clone isolation, forced non-cloning fallback, external symlink rejection and capacity refusal.

`managed-apps.json` and `managed-apps.log`: actual shipping creator produced two strictly signed per-device bundles using the installed host executable/runtime at SHA-256 `37d1db56fea7bc54ccafe684a9489ce415178ffb35f5039bde058b1424701e4a`. This is the earlier DMG-installed 0.1.2 candidate, preceding the independent-review catalog remediation; wrappers were created and indexed but were not launched. The helper/executable is not claimed to contain the later fixes. Metadata assertions used real lsregister/mdimport/mdls/mdfind, with online results scoped to the exact newly created test root. Friendly full-name search returned the generated application. Online indexing took 1.44 seconds and offline global disappearance 0.12 seconds in the final candidate run. Feature-off preserved both records while hiding their bundles. Two independently executed workers contending on the same reservation produced exactly one admission and one busy refusal.

The real 58,517,149-byte runtime copied 28 files by explicit APFS COW clone with no full-file copies in 4.7 ms. Observed free-space change was 57,344 bytes; concurrent filesystem activity means that delta is an observation rather than an exact unique-extent accounting. Bundle factory/icon/signing took 0.78 seconds. The 1000-record stable polling benchmark uses synthetic metadata/directories, and measured a maximum 0.081 seconds across ten iterations; it is not a 1000-app icon/build/indexing test.

Canonical existing ancestors now use realpath and comparisons use stable derived paths. The final harness cleans its active wrappers on assertion failure and retains successful signed bundles only under private noindex roots.

## Independent-review remediation (new candidate pending)

The independent reviewer correctly rejected the earlier candidate: a late unregister could finish after an acknowledged current register with no compensating register, and blocking flock prevented prompt helper shutdown. The earlier success evidence remains point-in-time evidence and does not override these release blockers.

The source now compensates both stale external-effect directions. Consistent duplicate current-register acknowledgements are idempotent; late/duplicate unregisters retain a corrective current register without removing a successor receipt. Existing unregister paths must still validate as exact owned managed/manual bundles; a foreign replacement is refused before Launch Services is called. Catalog lock admission uses LOCK_NB with a monotonic 150 ms deadline, checks cancellation, and marks descriptors close-on-exec.

A persisted cohort availability policy denies dispatch even for records beyond the first finite move batch. Location reconciliation journals at most 64 transitions before moving, and registration effects may be acknowledged in a batch of at most 64 with one durable journal. Read-only checks reuse only a manifest cached under flock with exact inode/size/mtime/ctime fencing; any independent atomic writer invalidates it. Large copies, signing, Android work and Launch Services remain outside the lock. Root ancestry is rechecked before directory creation/open, including absent roots whose parent was replaced by a symlink after initialization.

`catalog-remediation-tests.txt` currently records 23 passing catalog cases, including independent review regressions, duplicate effects, cross-writer cache invalidation, finite lock admission, 192-row progress/denial/restart, and ancestor replacement. `managed-apps.json` additionally measures 1000 complete synthetic metadata-fixture transitions: online 1.62 seconds and offline 1.64 seconds, 16 waves each; maximum reconcile lock work 79 ms, completion batch 56 ms, and 64 pre-dispatch checks 41 ms. These transition timings acknowledge simulated external effects and do not include 1000 real Launch Services executions or Android app builds. The real two-bundle Spotlight test uses unique synthetic device IDs so concurrent real emulator cohorts cannot contaminate its queries.

Pending final acceptance includes a rebuilt DMG-installed candidate with these fixes, actual helper shutdown under a held lock, the all-app GUI cohort/background availability tests owned by Systems, and independent QA approval. No physical Pixel claim is made.


The final remediation also persists a changed cohort deny policy before per-row filesystem work. A missing or foreign row cannot roll it back or prevent healthy rows from being hidden. Row failures retain bounded actionable issues with a 60-second retry delay, excluded from immediate-continuation progress counts. Explicit Add All reservation clears that row's delay. A genuinely deleted previous generation can be repaired while its full metadata is retained in `missingHistory`; any existing foreign replacement is refused before publication, with its bytes preserved. The three additional cases exercise durable global denial despite a poison row, healthy-row progress plus deleted-wrapper repair, and foreign replacement refusal/cleanup. `deny-policy-initial.log` preserves the failing regression before this fix.

Latest metadata harness rerun passed after the policy/quarantine/repair fixes. It used the then-installed candidate executable as the source bundle without launching it; its exact SHA is recorded in managed-apps.json.
